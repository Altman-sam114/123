# v4.7 明末 AI doctrine 首片记录

完成日期：2026-07-05

## 1. 目标

- 让默认 AI / fallback 将军池开始体现明末势力差异，而不是继续沿用 Germany aggressive / 其他 balanced 的二战遗留口径。
- 让明廷、后金/清、大顺、大西和地方中立在 `ZoneCommanderAgentConfig` 的默认 `commandStyle` 与 `skills` 上具备可读 doctrine：
  - 明廷：谨慎、防京畿、保粮、守城关。
  - 后金/清：进取、旗骑、合围、截援。
  - 大顺：进取、扩粮、破弱城、巩固中原。
  - 大西：进取、流动作战、夺粮、扰后。
  - 地方中立：谨慎、自保、守城镇。
- 保持 AI 输出仍为 `ZoneDirective` / `TheaterDirective`，最终仍经 `WarCommandExecutor -> RuleEngine` 执行。

## 2. 关键实现

- 新增 `ZoneCommanderDoctrine`：
  - `profile(for:)` 按势力返回默认名称、`CommandStyle` 和技能标签。
  - `defaultConfig(for:idPrefix:)` 统一生成 `ZoneCommanderAgentConfig`。
- `ZoneCommanderAgent.makeDirective` 在 `BinaryTacticClassifier` 后应用势力 tactic 偏置：
  - 明廷进攻优先火器压制，防守优先层层设防/固守。
  - 清方进攻优先突骑破阵，多个敌区时可转合围。
  - 大顺进攻优先破围。
  - 大西进攻优先流动作战。
  - 地方中立进攻只做低投入佯攻/正攻，防守固守。
- `TheaterCommanderPool.defaultConfig(for:)` 改用 `ZoneCommanderDoctrine`：
  - 显式 `.zoneDirective` 路径和元帅 fallback 路径都继承同一 doctrine。
- `MockAICommander.defaultConfig(for:)` 改用同一 doctrine：
  - MockAI envelope 不再把所有非德军势力都当作 balanced。
- `AppContainer.buildCommanderPool(state:registry:)` 的空 registry fallback 改用 `TheaterCommanderPool.automatic(for:)`：
  - 默认 app 启动/缺将领资料时也继承同一 doctrine，不再手写旧 aggressive / balanced 配置。
- `SimulatedMarshalLLMClient.offensiveTactic` 开始读取势力 doctrine：
  - 默认元帅 JSON 上游同态进攻下也会区分明廷火器压制、清方合围/突骑、大顺破围、大西流动作战。
  - 当前补充把明末 `strategicIntent`、每条 `TheaterDirective.rationale`、编译后的 `theaterContext` 和 `MarshalAgent.resolve` fallback 诊断改成军机/督师中文口径，避免军机复盘中继续出现 `Simulated marshal JSON`、`Compiled zone directives` 或 `Fallback TheaterCommanderPool used` 等调试文案；legacy 德/盟分支仍保留英文诊断便于阿登回归。
  - 该变化仍只生成 `TheaterDirectiveEnvelope`，再经 `TheaterDirectiveDecoder -> TheaterDirectiveCompiler -> ZoneDirective` 执行。
- `AgentPanelView` 军机复盘牌读取 `ZoneCommanderDoctrine.profile(for: directive.faction)`：
  - 每条 `WarDirectiveRecord` 下方只读展示势力军略、指挥风格、技能标签和战术偏向。
  - 该展示只翻译既有 doctrine，方便解释明廷谨守、清方合围、大顺破城、大西流动作战等 AI 倾向，不新增持久字段或命令入口。
- `AgentPanelView` 新增只读“诸势军略”总览：
  - 明末剧本下遍历 `Faction.mingLaunchCases`，对明廷、后金/清、大顺、大西和地方中立集中展示势力旗号、军略名、指挥风格、前两项技能标签和战术偏向。
  - 该总览只读取 `ZoneCommanderDoctrine.profile(for:)` 与既有显示 formatter，不新增 doctrine 状态，不触发命令，不写塘报，不改变默认配置、tactic 偏置、AI prompt、`WarCommandExecutor` 或 `RuleEngine`。
- Legacy Agent D / 本地 LLM 预留链路语境同步：
  - `AgentPromptBuilder` 在明末势力下把 system / user prompt 改为军机语境，强调中华世界局势、军政钱粮、火器城防、方面军调度和天下五线压力，同时继续强制 JSON schema、命令 enum 和校验边界不变。
  - `MockAIClient` 在明末势力下不再围绕 Bastogne 生成 intent / reason，而是按当前未控要冲、`CampaignAISummary.activeTasks`、粮草、城关、前线/纵深/驻防三层生成中文军令理由；legacy 德/盟分支继续保留 Bastogne / v0.33 deployment 回归文案。
  - 当前补充把 `AgentPromptBuilder` 的明末部队粮草摘要和 `MockAIClient` 的明末整粮理由从 `SupplyState.rawValue` 改为“有粮 / 缺粮 / 断粮被围”，避免军机案卷和本地 LLM prompt 直出 `lowSupply`、`encircled` 等调试值；legacy 德/盟分支仍保留英文 raw 值便于阿登回归。
  - `TurnManager.contextSummary` 在明末势力下输出“本方军伍、已知敌情、要冲、钱粮、朝议、五线态势”的中文摘要，legacy 德/盟分支保留旧英文摘要。
  - `GameAgent.sample` 为明末 fallback agent 提供“军机职责、粮草、城关、州府、天下局势”人格 prompt，legacy 分支保留旧英文 prompt；`AgentRole.displayName` 与 `GamePhase.displayName` 显示为主上/督师/总兵、军机行动/玩家行令。
  - 该组改动只影响 legacy Agent D prompt、模拟 AI 说明和 UI/记录可读文本，不改变 `AgentDecisionEnvelope`、`AgentOrder` schema、parser、mapper、`Command`、`ZoneDirective`、`WarCommandExecutor`、`RuleEngine` 或默认元帅执行权威。
- `CommandSystemTests` 增加语义用例：
  - 同样的边界兵力比下，明廷 cautious 默认选择防守，清方 aggressive 默认选择进攻。
  - 同样可进攻战况下，清方、大顺、大西分别生成突骑破阵、破围和流动作战 directive。
  - 同一元帅 front 摘要下，模拟元帅 JSON 会按清方、大顺、大西、明廷输出不同 tactic。
  - 大顺、大西、地方中立的默认风格和技能标签可被测试读取。

## 3. 非目标

- 不新增新 AI 管线，不接真实 LLM，不改 prompt schema。
- 不把 legacy Agent D 重新设为默认战争 AI 主路径。
- 不绕过 `Command` / `ZoneDirective` / `WarCommandExecutor` / `RuleEngine`。
- 不直接修改 `GameState`、hex 控制、region 聚合、经济账本、胜负、外交或事件。
- 不新增持久 doctrine 状态；本片只是默认配置、战术分类和 tactic 选择偏置。
- 不调整战斗伤害、移动、补给、围城或 `AttackIntensity` 的规则效果。

## 4. 后续

- 已在军机复盘牌中显示 doctrine 标签，并在“诸势军略”中横向比较明末诸方 AI 势力性格；后续可继续做更细的 tooltip、筛选或截图验收。
- 可结合战役五线态势，把大顺对开封/洛阳/西安、大西对湖广粮区、清方对山海关/北京的目标偏好做得更强。
