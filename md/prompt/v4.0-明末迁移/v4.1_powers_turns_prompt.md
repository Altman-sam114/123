# v4.1 明末多势力、外交关系和通用回合编排实现提示词

> 本提示词交给后续 Agent B 使用。执行前必须读取 `AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`md/plan/plan.md`、`md/prompt/v4.0-明末迁移/codex-v4.0-明末aiagent迁移总提示词.md` 和 `md/prompt/v4.0-明末迁移/v4.0_audit_and_contract.md`。

当前状态补记：本工作树已经开始落地 v4.1 兼容层，包含 `Faction` 多势力 case、`DiplomacyState` 关系 helper、`turnOrder` / human / AI 控制数组、通用 end turn 与 AI 运行条件、主路径 `.opponent` 调用替换。后续 Agent B 接手时应先核对实际 diff 和轻量检查结果，再决定是补齐 v4.1 收尾还是进入 v4.2 数据迁移。

---

## 1. 本轮目标

把当前二元 `germany/allies` 底座升级为明末多势力兼容层，并为后续明末剧本接入扫清最核心的规则阻塞。

必须达成：

- `Faction` 至少能表达 `ming`、`qing`、`dashun`、`daxi`、`localNeutral`。
- 保留 `.germany` / `.allies` legacy case，旧阿登 JSON 可继续解码。
- 新增统一关系判断入口，不再新增 `Faction.opponent` 调用点。
- 回合编排不再只能写死 `.germany -> .allies -> .germany`。
- `CommandValidator` 对玩家和 AI 仍对称，只允许 active faction 行动。
- 中立控制方不被错误 fallback 到明廷、Allies 或任意交战方。

---

- 不迁移兵种、生产和经济资源；v4.3 / v4.4 再做。
- 不做发布级 UI；v4.6 再做。
- 不接入真实 LLM。
- 不删除 Legacy Agent D。
- 不跑 Xcode / XCTest / 模拟器 / Probe / Smoke / Stage Regression / Full / 性能测试。

---

## 3. 当前审计依据

v4.0 审计确认以下阻塞点：

- `WWIIHexV0/Core/Faction.swift` 只有 `.germany` / `.allies`，并提供一对一 `opponent`。
- `WWIIHexV0/Core/GamePhase.swift` 固定 `.germanAI` / `.alliedPlayer`。
- `WWIIHexV0/Rules/CommandExecutor.swift` 固定二元 end turn。
- `WWIIHexV0/Rules/CommandValidator.swift` 用阶段名绑定行动阵营。
- `WWIIHexV0/App/AppContainer.swift` 和 `WWIIHexV0/Turn/TurnManager.swift` 只为 Germany 默认运行 AI。
- `WarCommandExecutor`、`SupplyRules`、`RegionSupplyRules`、`FrontLineManager`、`AgentContexts`、`ZoneCommanderAgent` 仍有 `.opponent` 调用。
- `ScenarioDefinition` 只有 `playerFaction` / `aiFaction` 二元字段；可本轮保留兼容，但应准备通用 turn order。

## 4. 建议修改顺序

### 4.1 Faction 兼容扩展

文件：`WWIIHexV0/Core/Faction.swift`

建议：

- 新增 case：
  - `ming`
  - `qing`
  - `dashun`
  - `daxi`
  - `localNeutral`
- 保留：
  - `germany`
  - `allies`
- `displayName` 增加中文展示：
  - 明廷、后金/清、大顺、大西、地方中立
  - Germany / Allies 仍作为 legacy 显示。
- 将 `opponent` 标注为 legacy。若不能一次性删除，必须在注释中写清只供旧二元阿登路径 fallback 使用；新逻辑不得继续新增调用。
- 如需要 UI / MapEditor 避免把 legacy 和明末混在同一选择器，可新增：
  - `static var legacyCases: [Faction]`
  - `static var mingLaunchCases: [Faction]`
  - `var isLegacyWWIIFaction: Bool`

### 4.2 外交关系判断入口

优先复用：`WWIIHexV0/Core/DiplomacyState.swift`

新增或补齐最小 helper：

```swift
func isHostile(_ lhs: Faction, _ rhs: Faction) -> Bool
func isFriendly(_ lhs: Faction, _ rhs: Faction) -> Bool
func canAttack(attacker: Faction, target: Faction?) -> Bool
func canEnterTerritory(faction: Faction, controller: Faction?) -> Bool
```

要求：

- `nil` controller 表示无控制方，默认可进入或可占领应由占领规则决定。
- `.localNeutral` 不是任何势力的自动敌人；是否可攻击由外交/叛乱/剧本规则决定。v4.1 可先设为默认非友军、非主动交战，具体行为在规则调用处保守处理。
- legacy Germany / Allies 的关系可初始化为 atWar，保证旧阿登路径不退化。

### 4.3 替换高风险 `.opponent` 调用

优先改运行时规则，不急着改测试 fixture。

第一优先级：

- `WWIIHexV0/Rules/SupplyRules.swift`
- `WWIIHexV0/Rules/RegionSupplyRules.swift`
- `WWIIHexV0/Rules/RegionCombatRules.swift`
- `WWIIHexV0/Commands/WarCommandExecutor.swift`
- `WWIIHexV0/Agents/AgentContexts.swift`

要求：

- 敌控判断必须经 `DiplomacyState` 或关系 helper。
- 不要写 `otherFaction != faction` 等价为敌人。
- 对 `nil` / `localNeutral` 明确分支，不要 fallback 到旧 Allies。

第二优先级：

- `WWIIHexV0/Rules/FrontLineManager.swift`
- `WWIIHexV0/Agents/ZoneCommanderAgent.swift`

要求：

- 前线仍基于动态战区真实 hex 邻接。
- 多敌势力可先聚合为“hostile neighbor”，不要求 v4.1 完成复杂多边前线 UI。

### 4.4 通用回合编排

推荐最小做法：

- 在 `ScenarioDefinition` 增加可选字段：
  - `turnOrder: [String]?`
  - `humanControlledFactions: [String]?`
  - `aiControlledFactions: [String]?`
- 旧 `playerFaction` / `aiFaction` 保留。
- 在 `GameState` 或回合 helper 中建立当前可用 turn order：
  - 若 scenario 有 `turnOrder`，使用它。
  - 否则 fallback `[aiFaction, playerFaction]` 或旧 Germany / Allies。
- `CommandExecutor.executeEndTurn` 不再 switch `.germany/.allies`；改为找当前 active faction 在 turn order 中的下一个势力。
- `GamePhase` 可先保留 legacy case，但新增或使用通用解释层：
  - `humanAction`
  - `aiAction`
  - `resolution`
  若一次性改 enum 风险过高，可先增加 helper，让 legacy phase 不再决定阵营身份。

### 4.5 AI 运行条件

文件：

- `WWIIHexV0/App/AppContainer.swift`
- `WWIIHexV0/Turn/TurnManager.swift`

要求：

- `shouldRunAI(for:phase:)` 不得只 switch Germany / Allies。
- 旧阿登默认可继续 Germany AI、Allies 玩家。
- 新字段存在时，按 `aiControlledFactions` / `humanControlledFactions` 判断。
- 观察者模式可让 human faction 也走 mock AI，但必须明确由 observer flag 开启。

### 4.6 MapEditor 和 UI 暂存处理

MapEditor 本轮只做必要兼容：

- 如果 `Faction.allCases` 会把 legacy 和明末势力都暴露到编辑器，可以先改用 `Faction.mingLaunchCases` 或保留 legacy 选择器并记录 v4.2 再迁移。
- 不要在 v4.1 顺手做完整编辑器术语迁移。

UI 本轮只修编译和明显显示名：

- 不做发布级明末 UI。
- 若新增 case 导致 `TerrainStyle` switch 不完整，给明末势力设置临时但可区分的颜色。
- 不改 `UnitNode` NATO 图形；v4.6 处理。

## 5. 关键禁止项

- 不把 `Faction.allCases` 扩展后直接用于旧阿登胜负判断、经济初始化或 MapEditor 导出而不审查影响。
- 不把 `.localNeutral` 当成可自动攻击的敌军。
- 不把 region 控制权当战术权威。
- 不绕过 `Command` / `ZoneDirective -> WarCommandExecutor -> RuleEngine`。
- 不删除旧阿登 JSON、旧 tests 或 Legacy Agent D。
- 不改 `.xcodeproj`，除非确实新增 Swift / JSON 文件且无法避免；若改，必须跑 `plutil -lint`。

## 8. 验收标准

- 旧阿登 scenario 仍有兼容路径。
- 明末五类势力可被 `Faction` 表达。
- 敌我判断有统一 helper，新增代码不继续依赖 `.opponent`。
- 至少核心规则中的敌控/敌军判断开始迁移到关系 helper。
- 回合推进有通用 turn order 或明确的兼容层，不再只能二元 switch。
- `AppContainer` 的 AI 运行条件可支持多势力配置。
- 文档明确哪些运行时代码仍保留 legacy 二战语义。
- 本机只运行轻量检查，并如实记录未跑重测试。
