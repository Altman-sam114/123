# v4.7 明末胜负链、战役目标面板与本旬任务链记录

日期：2026-07-05

本记录对应明末迁移 v4.7 的胜负链与战役目标面板首片。目标是把 `崇祯十五年：天下裂变` 的主要天下局势目标先接入 `BattleObjectiveSummary` / `VictoryRules`，并让玩家在局内看见各势力距离胜负条件还差哪些城关。

## 1. 本轮目标

- 保留 legacy 阿登胜负规则，不破坏旧测试板和旧数据 fallback。
- 对 `chongzhen_1642` 剧本启用明末胜负规则：
  - 清军控制山海关和北京，判定后金/清胜。
  - 大顺控制开封、洛阳和西安，判定大顺胜。
  - 大西控制荆州和武昌，判定大西胜。
  - 明廷在最终回合守住北京、山海关和武昌，判定明廷胜。
  - 最终回合未触发明确条件时，按 objective points 计算关键目标归属。
- 让顶部朝报令条的胜负 badge 显示简短胜负理由。
- 新增只读“目标”面板，让玩家看到四条胜负线、关键城关控制方和 objective points 领先方。
- 在目标面板加入只读战役提示，让玩家看到松锦余波、催饷安民、粮道告急、军机复盘、开封围城压力和目标线压力等 v4.7 教程/历史 cue。
- 在目标面板加入只读天下五线态势，让玩家一眼看到天下、政策、经济、科技、军事哪条线告急或进入主线。
- 在目标面板加入只读本旬任务链，让玩家按当前压力看到军事守关、政策征饷安民、经济粮链、科技火器修城和终局名分等当旬重点。
- 在大顺控制开封时，额外派生“救援开封压力”急务任务，并让目标面板和任务塘报可定位 `obj_kaifeng`；该提示不等于真实多回合围城状态。
- 在目标面板加入只读阶段战局链，让玩家按 1-20 回合理解山海关屏障、河南秦陕粮链、湖广粮道、朝廷四线取舍、火器修城和终局名分线。
- 将同一套天下五线态势送入 Agent 和元帅摘要，让 AI/军机链路不只看到局部前线，也能看到中华世界局势、政策、经济、科技、军事压力。
- 让朝廷四线主议读取同一套明末战役线压力，把破关入京、河南秦陕粮链、湖广粮道和终局名分线转成修城、粮台、火器、赈济或征饷权重。
- 让目标面板的关键城关 chip 可定位对应 hex / 州府，帮助玩家从胜负线回到舆图和州府牌。
- 结束回合时将当前战役提示以去重塘报写入 `eventLog`，让历史/教程 cue 进入复盘记录。
- 结束回合时将当前急务/主线任务以去重塘报写入 `eventLog`，让玩家在塘报战记里复盘当旬军政钱粮火器重点。
- 关键 objective 因合法移动占领换手时写入塘报，帮助玩家看到北京、山海关、开封等天下要冲变化。
- 保持所有判定只读取 `GameState`、`MapState` 和 objective 控制权，不从 UI 或 Agent 直接改权威状态。
- 将 `ScenarioDefinition.victoryConditions` 带入 `GameState`，让目标摘要和胜负判定优先读取剧本条件，减少明末目标硬编码。

## 2. 已完成改动

- `Objective` 新增 `points`：
  - `DataLoader` 从 `ScenarioDefinition.objectives[].points` 写入 `MapState.objectives`。
  - `ScenarioDefinition.ObjectiveDefinition` 和 `Objective` 自定义 decode，旧剧本、旧存档或旧测试数据缺少 `points` 时默认 0。
- `MapState` 新增按 objective id 查询：
  - `objective(id:)`
  - `controllerOfObjective(id:)`
- `VictoryReason` 新增明末原因和 `displayName`：
  - `mingHoldsMandateAtFinalTurn`
  - `qingBreaksPassAndCapital`
  - `dashunControlsCentralPlain`
  - `daxiControlsHuguangBase`
  - `mingHoldsMostKeyObjectivesAtFinalTurn`
  - `mingMandateCollapsedAtFinalTurn`
- `VictoryRules` 分流：
  - `scenarioId.hasPrefix("chongzhen_1642")` 时读取 `BattleObjectiveSummary` 并走明末胜负链。
  - 其他剧本继续走 legacy 阿登胜负链。
- 新增 `BattleObjectiveSummary`：
  - 优先从 `GameState.victoryConditions` 编译四条胜负线；旧存档或缺失条件时保留内置 fallback。
  - 从 `GameState` / `MapState` 派生每个目标点控制方、目标点分值和当前领先方。
  - 派生 `Cue` 列表，按当前回合、当前势力、缺粮部队、AI 指令记录、开封控制方和目标线进度生成最多 4 条只读战役提示。
  - 派生 `CampaignTask` 列表，按胜负线压力、开封控制方、当前回合、明廷火器/炮队支点和 objective points 领先方生成本旬任务链，覆盖军事、政策、经济、科技和终局天下名分。
  - 派生 `CampaignStage` 列表，按胜负线进度、当前回合、明廷火器/炮队支点和 objective points 领先方生成阶段战局链。
  - 派生 `CampaignLineBrief` 列表，把阶段链和任务链聚合成天下、政策、经济、科技、军事五线压力、告急状态和当前摘要，供目标面板扫读。
  - `Cue` 提供塘报正文和分类，供结束回合时写入事件日志。
  - `VictoryRules` 与 UI 共用该摘要，避免胜负规则和目标展示口径分叉。
- 新增 `CampaignAISummary`：
  - 从 `BattleObjectiveSummary` 只读派生，不保存进 `GameState`。
  - 将领先势力、天下/政策/经济/科技/军事五线压力、告急状态、任务数量和急务/主线任务转成 `Codable` 摘要。
  - 非明末剧本返回 `.empty`，legacy 阿登 prompt 只看到“旧剧本目标摘要未启用明末五线态势”。
- `AgentContext` 新增 `campaignSummary`：
  - `AgentContextBuilder` 每次从当前 `GameState` 即时派生。
  - `AgentPromptBuilder` 在用户 prompt 中追加“Campaign mandate and five-line pressure”段落。
  - `TurnManager.contextSummary` 把五线态势并入 AI 回合摘要。
- `MarshalBattlefieldSummary` 新增 `campaignSummary`：
  - `MarshalBattlefieldSummarizer` 从当前 `GameState` 派生同一摘要。
  - `schemaVersion` 从 8 升到 9，表示元帅摘要新增战役五线字段。
  - `SimulatedMarshalLLMClient` 的 envelope summary 和 strategic intent 都会引用该摘要，让默认元帅链路同时看到钱粮、朝议和天下五线压力。
- `CourtStrategySummary` 读取明末战役线压力：
  - `campaignPolicyPressure(from:)` 从 `BattleObjectiveSummary` 只读派生主议/备议加权，不保存进 `GameState`。
  - 清方已推进破关入京线时，提高修城固守、粮台转运和火器整备权重。
  - 大顺推进河南秦陕粮链时，提高粮台转运、赈济安民和征饷权重。
  - 大西推进湖广粮道时，提高粮台转运和修城固守权重。
  - 临近终局且明廷名分线未稳时，提高修城固守和火器整备权重。
  - `rationale` 会追加“战役线提示”，帮助朝廷面板、HUD、天下面板和 AI 摘要解释主议来源。
- `CommandExecutor.appendBattleCueEvents`：
  - 在 `endTurn` 中读取当前 `BattleObjectiveSummary.cues`。
  - 用 `battle-cue-<turn>-<faction>-<cue id>` 作为 `relatedRecordId` 去重。
  - 只追加 `eventLog`，不改变 hex、region、economy、victory、AI 指令或任何规则权威。
- `CommandExecutor.appendBattleTaskEvents`：
  - 在 `endTurn` 中读取当前 `BattleObjectiveSummary.tasks`。
  - 仅把急务/主线任务按优先级写入塘报，最多 3 条。
  - 用 `battle-task-<turn>-<faction>-<task id>` 作为 `relatedRecordId` 去重。
  - 只追加 `eventLog`，不改变任务状态、hex、region、economy、victory、AI 指令或任何规则权威。
- `CommandExecutor.appendObjectiveControlEventIfNeeded`：
  - 在合法移动占领 objective hex 后读取占领前后的 `HexTile.controller`。
  - 仅对 `chongzhen_1642*` 明末剧本追加 `regionOwnerChange` 类塘报，正文记录目标名、原控制方、新控制方和要冲分。
  - 只追加 `eventLog`，不改变 objective 控制、胜负判定、目标摘要、经济、AI 指令或任何规则权威。
- `DataLoader.loadGameState` 现在把剧本 JSON 的 `victoryConditions` 写入 `GameState.victoryConditions`，`GameState` 旧存档解码缺失该字段时默认空数组。
- 新增 `BattleObjectivePanelView`：
  - `RootGameView` 信息面板新增“目标”tab。
  - 面板展示清破关入京、大顺据中原秦陕、大西据湖广粮区、明廷守京师关口四条目标线。
  - 面板新增“战役提示”区，用史势、政务、钱粮、军务、军机五类 cue 提醒玩家查看地图、朝廷、粮道和军机复盘。
  - 面板新增“天下五线态势”区，用压力条、告急状态和急务数量把天下、政策、经济、科技、军事五线合并为一眼可扫读的局势板。
  - 面板新增“本旬任务链”区，用急务、主线、留意优先级提示当前军事、政策、经济、科技任务，任务可选定位相关 objective。
  - 面板新增“阶段战局链”区，用天下、政策、经济、科技、军事标签展示 1-20 回合可玩重点。
  - 面板展示终局要冲分，让玩家能看见 objective points 归属。
  - 目标城关 chip 通过 `onFocusObjective` 回调调用 `AppContainer.focusObjective(_:)`，只更新 `selectedHex`、`selectedRegionId`、高亮和交互日志；`RootGameView` 在紧凑信息面板下切到州府牌，便于玩家查看目标 hex / 州府。
- `HUDView` 胜负 badge 从只显示“某势力胜”升级为“某势力胜 · 胜负理由”。
- `RuleEngineCoreTests` 增加明末胜负规则和目标摘要语义用例，覆盖清、大顺、大西、明廷最终守线、目标线进度、分值领先方、开局提示、缺粮提示、开封围城压力提示、目标线压力提示、天下五线态势、本旬任务链、压力任务切换、结束回合提示塘报和任务塘报入册。
- `RuleEngineCoreTests` 增加五线态势进入 Agent 与元帅摘要的语义用例，覆盖 `AgentContext.campaignSummary`、`TurnManager.contextSummary`、`MarshalBattlefieldSummary.schemaVersion == 9` 和急务/主线任务进入元帅摘要。
- `RuleEngineCoreTests` 增加战役线影响朝廷主议的语义用例，覆盖清方控制山海关后 `CourtStrategySummary.recommendedFocus == .fortify`、备议包含粮台转运、理由包含“破关入京线已动”。
- `RuleEngineCoreTests` 增加明末 objective 换手塘报用例，覆盖清军占领北京后写入 `objective-control` relatedRecordId 和目标换手正文。
- `BoardInteractionTests` 增加目标定位语义用例，覆盖定位 objective 后清除单位选择/移动攻击高亮、选中目标 hex 与 region、只写交互日志且不提交命令。

## 3. 非目标

- 不新增会修改地图、钱粮或胜负状态的历史事件系统、教程触发器、灾荒效果、真实多回合围城状态或可执行多回合战役目标链；本轮战役提示、开封围城压力、天下五线态势、本旬任务链和阶段战局链只读派生，回合末只写塘报日志。
- 不让目标换手塘报反向驱动胜负、事件效果、经济或外交；它只记录真实移动占领已经造成的 objective hex 控制变化。
- 不让 `CampaignAISummary` 自动生成或执行政策、经济、科技、军事命令；它只扩展 Agent/元帅可读上下文，最终命令仍必须走 `Command` / `ZoneDirective` / `WarCommandExecutor` / `RuleEngine`。
- 不让 `CourtStrategySummary` 的战役线加权直接执行朝廷项目；它只改变只读主议/备议排序和理由，玩家仍需通过 `Command.enactCourtProject -> CommandValidator -> EconomyRules` 执行项目。
- 不新增完整政策/科技树，也不让政策直接改胜负。
- 不新增地图相机控制、自动滚动或 SpriteKit 镜头 API；目标定位首片只复用现有选中 hex / region 状态。
- 不改变 `Command`、`ZoneDirective`、`WarCommandExecutor`、`RuleEngine` 权威链路。
- 不删除或重写 legacy 阿登胜负规则。
- 不声称完成发布级胜负体验；事件提示、教程解释、目标点击跳转、截图验收仍后续继续。
