# v4.7 明末胜负链、战役目标面板、本旬任务链与目标定位舆图反馈记录

日期：2026-07-05

本记录对应明末迁移 v4.7 的胜负链与战役目标面板首片、目标控制方旗号小片、目标定位舆图反馈小片、目标面板天下棋眼小片、舆图要冲分布小片、朝廷面板廷议要冲小片，以及钱粮面板府库四线牵引小片。目标是把 `崇祯十五年：天下裂变` 的主要天下局势目标先接入 `BattleObjectiveSummary` / `VictoryRules`，让玩家在局内看见各势力距离胜负条件还差哪些城关，并在关键城关 chip 上直接扫读当前控制方旗号；点击目标、任务定位或天下棋眼定位后，可把对应胜负线更直观地落回舆图；舆图顶部和朝廷面板同步前置各势力要冲分与控制要冲数，钱粮面板则从府库视角补上政策、经济、科技、军事四线联读。

## 1. 本轮目标

- 保留 legacy 阿登胜负规则，不破坏旧测试板和旧数据 fallback。
- 对 `chongzhen_1642` 剧本启用明末胜负规则：
  - 清军控制山海关和北京，判定后金/清胜。
  - 大顺控制开封、洛阳和西安，判定大顺胜。
  - 大西控制荆州和武昌，判定大西胜。
  - 明廷在最终回合守住北京、山海关和武昌，判定明廷胜。
  - 最终回合未触发明确条件时，按 objective points 计算关键目标归属。
- 让顶部朝报令条的胜负 badge 显示简短胜负理由。
- 新增只读“目标”面板，让玩家看到四条胜负线、关键城关控制方和 objective points 领先方。
- 在目标面板 header 后新增只读“天下棋眼”，把要冲分领先方、当前最急五线、本旬先手和可定位目标前置到第一眼。
- 在顶部舆图“天下急势”内新增只读“要冲分布”，从 `BattleObjectiveSummary.scoreRows` 横向展示各势力 objective points、控制要冲数和领先方，让地图第一视野更直接呈现中华世界局势。
- 在朝廷面板“朝议批票”后新增只读“廷议要冲”，从同一 `BattleObjectiveSummary.scoreRows` 展示各势力 objective points、控制要冲数、本方分值和领先方，让朝议把中华世界局势接回政策、经济、科技、军事取舍。
- 在钱粮面板新增只读“府库四线牵引”，把 `FactionEconomyLedger` 库存/营造队列与当前势力 `CourtStrategySummary` 的政策、经济、科技、军事压力、主议和备议联读。
- 目标面板的关键城关 chip 会显示当前控制方旗号，帮助玩家在清破关入京、大顺中原秦陕、大西湖广粮道和明廷名分线之间快速扫读城关归属。
- 在目标面板加入只读战役提示，让玩家看到松锦余波、催饷安民、粮道告急、军机复盘、开封围城压力和目标线压力等 v4.7 教程/历史 cue。
- 在目标面板加入只读天下五线态势，让玩家一眼看到天下、政策、经济、科技、军事哪条线告急或进入主线。
- 在目标面板加入只读本旬任务链，让玩家按当前压力看到军事守关、政策征饷安民、经济粮链、科技火器修城和终局名分等当旬重点。
- 在大顺控制开封时，额外派生“救援开封压力”急务任务，并让目标面板和任务塘报可定位 `obj_kaifeng`；该提示不等于真实多回合围城状态。
- 在目标面板加入只读阶段战局链，让玩家按 1-20 回合理解山海关屏障、河南秦陕粮链、湖广粮道、朝廷四线取舍、火器修城和终局名分线。
- 将同一套天下五线态势送入 Agent 和元帅摘要，让 AI/军机链路不只看到局部前线，也能看到中华世界局势、政策、经济、科技、军事压力。
- 将同一套天下五线态势显式展示到军机复盘牌，让玩家复盘 AI 决策时能同时看到五线压力和当旬急务。
- 让朝廷四线主议读取同一套明末战役线压力，把破关入京、河南秦陕粮链、湖广粮道和终局名分线转成修城、粮台、火器、赈济或征饷权重。
- 让目标面板的关键城关 chip 可定位对应 hex / 州府，帮助玩家从胜负线回到舆图和州府牌。
- 让目标定位后的舆图有明确视觉反馈：聚焦城关显示“标”令牌、脉冲圈、目标名称、当前控制方，并用同色细线连接同一胜负线的相关城关。
- 结束回合时将当前战役提示以去重塘报写入 `eventLog`，让历史/教程 cue 进入复盘记录。
- 结束回合时将当前急务/主线任务以去重塘报写入 `eventLog`，让玩家在塘报战记里复盘当旬军政钱粮火器重点。
- 关键 objective 因合法移动占领换手时写入塘报，帮助玩家看到北京、山海关、开封等天下要冲变化。
- 保持所有判定只读取 `GameState`、`MapState` 和 objective 控制权，不从 UI 或 Agent 直接改权威状态。
- 将 `ScenarioDefinition.victoryConditions` 带入 `GameState`，让目标摘要和胜负判定优先读取剧本条件，减少明末目标硬编码。

  - `DataLoader` 从 `ScenarioDefinition.objectives[].points` 写入 `MapState.objectives`。
  - `ScenarioDefinition.ObjectiveDefinition` 和 `Objective` 自定义 decode，旧剧本、旧存档或旧测试数据缺少 `points` 时默认 0。
- `MapState` 新增按 objective id 查询：
  - `objective(id:)`
  - `controllerOfObjective(id:)`
- `VictoryReason` 新增明末原因和 `displayName`：
  - `mingHoldsMandateAtFinalTurn`

  - `mingHoldsMostKeyObjectivesAtFinalTurn`

  - `scenarioId.hasPrefix("chongzhen_1642")` 时读取 `BattleObjectiveSummary` 并走明末胜负链。
  - 其他剧本继续走 legacy 阿登胜负链。
- 新增 `BattleObjectiveSummary`：
  - 优先从 `GameState.victoryConditions` 编译四条胜负线；旧存档或缺失条件时保留内置 fallback。
  - 从 `GameState` / `MapState` 派生每个目标点控制方、目标点分值和当前领先方。

  - 派生 `CampaignStage` 列表，按胜负线进度、当前回合、明廷火器/炮队支点和 objective points 领先方生成阶段战局链。
  - 派生 `CampaignLineBrief` 列表，把阶段链和任务链聚合成天下、政策、经济、科技、军事五线压力、告急状态和当前摘要，供目标面板和朝廷面板扫读。

  - `VictoryRules` 与 UI 共用该摘要，避免胜负规则和目标展示口径分叉。
- 新增 `CampaignAISummary`：
  - 从 `BattleObjectiveSummary` 只读派生，不保存进 `GameState`。

## 3. 非目标

- 不新增会修改地图、钱粮或胜负状态的历史事件系统、教程触发器、灾荒效果、真实多回合围城状态或可执行多回合战役目标链；本轮战役提示、开封围城压力、天下五线态势、本旬任务链和阶段战局链只读派生，回合末只写塘报日志。
- 不让目标换手塘报反向驱动胜负、事件效果、经济或外交；它只记录真实移动占领已经造成的 objective hex 控制变化。
- 不让 `CampaignAISummary` 自动生成或执行政策、经济、科技、军事命令；它只扩展 Agent/元帅可读上下文，最终命令仍必须走 `Command` / `ZoneDirective` / `WarCommandExecutor` / `RuleEngine`。
- 不让军机复盘牌的五线展示触发命令、写塘报、改变 doctrine 或改写任何 `GameState` 权威状态；它只是 `CampaignAISummary` 的 SwiftUI 只读视图。
- 不让 `CourtStrategySummary` 的战役线加权直接执行朝廷项目；它只改变只读主议/备议排序和理由，玩家仍需通过 `Command.enactCourtProject -> CommandValidator -> EconomyRules` 执行项目。
- 不新增完整政策/科技树，也不让政策直接改胜负。
- 不新增地图相机控制、自动滚动或 SpriteKit 镜头 API；目标定位舆图反馈只新增 UI 状态和只读 SpriteKit 绘制，不移动镜头，不提交命令，不改变 objective 控制方。
