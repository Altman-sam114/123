# v4.8 明末发布候选记录：自动保存与继续战局首片

完成日期：2026-07-06

## 目标

本片只推进 v4.8 发布候选中的“新局 / 继续 / 重置”闭环：玩家操作后自动保存当前战局，可从 HUD 战局菜单或 macOS 战局菜单继续最近战局；新开战局会清除旧存档。

## 范围

- `AppContainer` 增加本地 `SavedGameSnapshot` envelope，使用 `schemaVersion`、`savedAt` 和完整 `GameState` 保存到本机 `UserDefaults`。
- 玩家底层命令成功后、玩家将令成功提交后、AI 回合结算后自动保存当前 `GameState`。
- `continueSavedGame()` 只恢复 `GameState`，并重建将领分配、清空选中态和高亮，避免旧 UI 临时状态污染续战。
- `resetGame()` 明确清除本机存档，再载入默认明末新局。
- `HUDView` / `NewGameButton` 把单一“新局”按钮升级为“战局”菜单，包含继续战局和新开战局。
- macOS `CommandMenu("战局")` 增加“继续战局”入口。
- AI 异步回合增加 run token；新局或续战时会让旧 AI task 的回写失效，避免旧回合覆盖新局/续战。

## 非目标

- 不保存 UI 选中态、图层、粮道开关、信息面板展开状态或最近交互日志。
- 不做多存档槽、存档列表、导入导出、云同步或 iCloud。
- 不新增设置面板、历史事件执行器、教程系统、真实美术资产或截图验收。
- 不改变 `Command`、`ZoneDirective`、`WarCommandExecutor`、`CommandValidator`、`RuleEngine`、胜负、经济、AI 决策、hex / region / theater / front / deploy 权威。

## 风险

- `GameState` 虽然已有兼容解码，但旧存档与未来剧本 JSON 变更之间没有迁移器；坏档会被忽略或续战失败。
- 存档保存在本机 `UserDefaults`，适合发布候选首片和单槽续战，不适合大型多存档管理。
- 未做运行时 UI 点击、真实续战、macOS 菜单或 iOS 触控验收；需通过 GitHub Actions 和后续授权运行检查继续确认。
