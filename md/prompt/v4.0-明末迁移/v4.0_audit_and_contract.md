# v4.0 明末迁移审计与合同

> 本文件是 v4.0 阶段大纲，用于把 `WWIIHexV0` 迁移到 AI Agent 驱动明末历史策略游戏前的审计、兼容层和题材合同沉淀下来。它不是源码实现记录；实现前仍必须读取 `AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本目录总提示词。

当前状态补记：v4.1 多势力兼容层和 v4.2 明末默认数据首片已继续推进；本文件中的阻塞清单保留原始审计语境，最新源码行为以 `md/flow/flow.md`、`update_log.md` 和 `v4.2_ming_scenario_data_record.md` 为准。

---

## 1. v4.0 目标

- 建立明末迁移的工程合同和术语合同。
- 找出二战硬编码、二元阵营假设、UI 文案残留和数据 schema 限制。
- 明确 v4.1-v4.8 的版本边界、并发 Agent 分工和检查要求。
- 先做兼容层和风险清单，不急着实现完整明末玩法。

## 2. 非目标

- 不一次性重命名 `WWIIHexV0`、`Division`、`Theater` 等源码类型。
- 不直接改写核心规则或默认剧本数据。
- 不恢复 Cabinet / Minister / StrategicDirective 旧污染。
- 不接入真实网络或本地 LLM。
- 不跑 Xcode / XCTest / 模拟器 / Probe / Smoke / Stage Regression / Full / 性能测试。

## 3. 必须保住的权威边界

- `HexTile.controller` 和 `Division.coord` 是战术权威。
- Region 只做战略聚合，不替代 hex。
- `regionToTheater` 是初始/基础战区，不是运行时推进权威。
- `hexToTheater` 是运行时动态战区权威。
- `hexToFrontZone` 是部署层动态归属权威。
- 玩家、AI、聊天命令都必须经过 `Command` / `ZoneDirective -> WarCommandExecutor -> RuleEngine`。

### 4.2 二元阵营假设

重点定位：

```text
enum Faction
Faction.opponent
GamePhase
activeFaction
playerFaction
aiFaction
canAttack
isHostile
canEnterTerritory
CommandValidator
TurnManager
AppContainer.runAIIfNeeded
```

输出要求：

- 标注会阻塞多势力的 public API。
- 区分“可以兼容保留旧 case”和“必须改为关系判断”的点。

当前阻塞 v4.1 的 public API 与处理状态：

- `Faction` 原先只有两个 case，且 `opponent` 是一对一反转。当前工作树已扩展 `ming/qing/dashun/daxi/localNeutral`，并保留 `.germany/.allies` legacy case；`opponent` 只作为旧 fallback 保留。
- `GamePhase` 原先用 `germanAI` / `alliedPlayer` 表示行动权限。当前已新增 `.aiAction` / `.humanAction`，并由 `GameState.actionPhase(for:)` 给多势力回合使用。
- `CommandExecutor.executeEndTurn` 原先固定 `.germany -> .allies -> .germany`。当前已改为按 `GameState.resolvedTurnOrder` 轮转。
- `AppContainer.shouldRunAI` 和 `shouldRunAIInSnapshot` 原先只为 Germany 跑 AI，Allies 只在观察者模式下运行。当前已改为读取 `aiControlledFactions` / `humanControlledFactions`。
- `TurnManager` 的 readiness 判断已放宽为 active faction + 非 resolution；是否运行由 AppContainer 控制。
- `ScenarioDefinition` 仍保留 `playerFaction` / `aiFaction` legacy 字段，同时已新增可选 `turnOrder`、`humanControlledFactions`、`aiControlledFactions`。
- `DiplomacyState` 已补齐 `canAttack`、`isHostile`、`isFriendly`、`canEnterTerritory` helper；攻击校验和若干运行时敌我判断已迁移，部分 UI / 旧规则层不等式仍需后续逐步审查。

当前可兼容保留的命名：

- `Faction` 可以短期继续作为规则层控制方类型，不急着改名为 `PowerId`。
- `Division` 可以短期继续作为源码模型名，但 UI 和数据展示必须抽出明末显示名。
- `Theater` / `FrontZone` 可以短期继续作为源码类型名，UI 展示迁移为方面、防区、镇守区。

### 6.1 v4.1-v4.8 风险清单

| 阶段 | 主要风险 | 降低风险的做法 |
|---|---|---|
| v4.1 | 多势力改造会触碰 `Faction`、`GamePhase`、`CommandExecutor`、`CommandValidator`、`TurnManager`、`AppContainer`，影响全局回合和命令合法性 | 先加兼容层和关系 helper，再逐点替换 `.opponent`；保留旧阿登 case 直到新剧本稳定。 |
| v4.2 | 新明末 JSON 需要 project resource phase、DataLoader 默认入口和 MapEditor bridge 同步，容易出现资源缺失或 bundle/source 路径分叉 | Project 文件只由一个 Agent 修改；每个新 JSON 用 `jq empty`；默认入口和 editor bridge 同步记录。 |
| v4.3 | 兵种迁移若直接删旧 enum case，会破坏旧数据和测试 | 新增明末 case 或模板兼容映射，旧 `tank` / `motorizedInfantry` 保留 legacy 解码。 |
| v4.4 | 资源名迁移可能只改 UI、不改规则语义，导致日志和生产项仍是二战 | 先定义资源显示适配，再迁移 `ProductionKind` 和 `EconomyRules`。 |
| v4.5 | 多层 Agent 容易绕过底层规则或恢复旧 Cabinet / Minister 污染 | 所有 Agent 输出 Codable directive；decoder 失败必须 fallback；不直接改 `GameState`。 |
| v4.6 | UI 明末化可能把规则写进 View 或让 SpriteKit 直接改状态 | UI 只读状态，操作仍经 `AppContainer` 和规则系统；视觉资产使用自制/生成/授权来源。 |
| v4.7 | 历史事件若直接改 controller / ledger，会破坏权威链 | 事件执行也要走统一 validator / executor 或明确的规则层入口。 |
| v4.8 | 发布候选若只看文档和静态检查，运行时风险无法排除 | 发布前需人工授权 Xcode build、模拟器/真机或 macOS 启动、10-20 回合观察者验证。 |

### 6.2 并发与文件边界建议

- v4.1 不建议并发改 `Core/Faction.swift`、`Core/GamePhase.swift`、`Rules/CommandExecutor.swift` 和 `Rules/CommandValidator.swift`；这些是同一接口合同，应由 Rules / Core Agent 串行处理。
- v4.2 可并发 Data / Scenario Agent 与 MapEditor Agent，但 `WWIIHexV0.xcodeproj/project.pbxproj` 只能由唯一 Project Agent 修改。
- v4.3 可让 UI Agent 只做显示名适配，不与 Rules Agent 同时改 `Division.swift` / `EconomyState.swift`。
- v4.5 的 Agent schema 先写文档和 DTO，再接 TurnManager；不要让 AI Agent 与 Rules Agent 同时改命令执行入口。

### 6.3 v4.1 最小接口合同草案

v4.1 开始实现前，建议采用以下最小合同：

- `Faction` 继续作为规则层控制方类型，新增 `ming`、`qing`、`dashun`、`daxi`、`localNeutral`，保留 `germany`、`allies` 为 legacy。
- `Faction.opponent` 标记为 legacy-only；新代码不得继续增加调用点。
- 新增关系判断入口，至少包含 `isHostile(lhs:rhs:in:)`、`isFriendly(lhs:rhs:in:)`、`canAttack(attacker:target:in:)`、`canEnterTerritory(faction:controller:in:)`。
- 回合推进改为读取 `turnOrder` 或等价数组；旧 `playerFaction` / `aiFaction` 只作为 legacy scenario fallback。
- `CommandValidator` 只判断 `division.faction == state.activeFaction` 和关系规则，不再用 `.germanAI` / `.alliedPlayer` 绑定阵营。
- 中立地块允许 `controller == nil` 或 `.localNeutral`；不得 fallback 到明廷或旧 Allies。
